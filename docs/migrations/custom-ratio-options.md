# 模型自定义画面比例

日期：2026-10-14。范围：模型参数配置、参考图与视频生成、输入快照；不扩展成片输出画幅。

## 使用

模型管理 → 协议与参数 → 支持的画面比例，可逐个输入服务商文档规定的值，按回车或点添加，点击 × 删除。常用比例是快捷选项，不会自动启用。自定义 JSON 协议可配置 `adaptive`、`21:9` 或服务商命名值，保留大小写；内置协议保持当前已实现的 `16:9`、`9:16`、`1:1` 限制。

服务商只支持 `adaptive` 时，删除其他选项，仅添加 `adaptive`；将请求中对应字段（例如 `metadata.ratio`）绑定为“画面比例”。分镜读取保存后的模型选项，“自适应（adaptive）”实际提交 `adaptive`。请求未绑定画面比例时提示选择不会写入请求；若有意保留固定值，须确认固定值与配置选项一致。配置不会自动改写 JSON 示例或服务商参数。

自适应由服务商决定生成视频画幅。成片合成仍单独选择现有固定输出画幅。选项被删除后，已有分镜保留旧输入、提示重新选择并禁用生成；后端也拒绝未配置值。历史运行及重试保持提交时的模型与参数快照。

每个选项为 1–64 个字符、区分大小写，不允许空白、控制字符或逗号；列表为 1–64 项，不允许重复。图片操作沿用每个比例显式配置输出尺寸的要求，视频比例不直接决定本地 FFmpeg 输出尺寸。

## 升级和回滚

沿用现有 `ratios: string[]`、`aspect_ratio: string`，无新增数据库表、无自动数据迁移，原三种比例配置保持原值。按 [发布与恢复](../release.md) 备份数据库、上传目录与凭据设施，再替换 EXE；不要从压缩包临时目录长期运行。

回退旧 EXE 后，自定义比例配置会因旧白名单而不可用。先备份并人工将新配置改回旧版支持的比例，或恢复升级前的完整备份；不要把历史 `adaptive` 快照批量改成 `16:9`。此轮不修改实际用户配置与数据。

## 验证范围

领域测试覆盖配置值、重复/空白/长度、大小写、内置协议限制和旧配置；SQLite 与生成用例覆盖保存后读取、首帧/直接参考生视频、未配置值拒绝、配置变化与快照隔离；本地 HTTPS 模拟接口覆盖嵌套 JSON 中实际发送 `adaptive`、异步完成和结果提取。浏览器回归覆盖键盘添加、删除、保存与刷新、窄屏、分镜选择与任务快照。

上述协议测试使用本地模拟服务，不代表服务商成功生成。此前一次真实失败定位确认 `seedance-2.5-global-token` 拒绝 `16:9`、只允许 `adaptive`；本次更新不再次发起真实计费生成，图片 Data URI 和其他远端参数兼容性仍须分别验证。

验证结果：后端全量测试（使用真实本地 FFmpeg/ffprobe）、vet、内嵌工具启动测试通过；前端 lint、63 项单元测试、生产构建和 64 项串行浏览器回归通过。Windows 单 EXE 的隔离验证覆盖 MP3/WAV 上传、原始字节下载、静态资源、本地 HTTP 合成、WebSocket、重启复用及缓存修复；最终报告与 EXE 摘要一同保存在发行目录。

打包复验曾两次遇到新目录下 FFmpeg 单次 `-version` 自检退出码 1，随后同一工具可以正常运行，首次失败原因未确定。启动自检现最多尝试三次、单次最多 10 秒、总预算 35 秒；仅重试本地只读版本检查，持续失败仍标记不可用，不影响模型请求的重试策略。包测试的启动等待相应延长。

仓库当前缺少开发指南引用的 `specs/model-protocol-integration/` 等规格文件；本次以代码、OpenAPI、现有操作指南及此次明确计划为实施依据，不宣称完成其他架构迁移。
