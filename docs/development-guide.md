# FrameFlow 开发与架构指南

日期：2026-10-09。状态：统一模型协议接入已实施；其余历史用例按本指南渐进迁移。

入口规则见 [AGENTS.md](../AGENTS.md)，方案取舍见 [架构治理决策](../specs/architecture-governance/design.md)。模型协议改造见 [实施记录](../specs/model-protocol-integration/plan.md) 和 [模型配置指南](model-protocols.md)。

## 一、现状与目标

现状：后端已使用 `domain / application / infrastructure / interfaces` 目录、Go + Gin 和 SQLite，前端为 Vue 3 + TypeScript。已有厂商注册表、任务持久化、版本检查和输入快照，优先演进这些资产。

本次已将 `domain/processor` 移至 `application/execution`，通过任务事件端口通知 WebSocket；四类生成按显式协议和参数配置执行，模型名仅用于配置预设与发现推荐。新增模型配置用例及 HTTP handler 分层。历史 application 中的 Gin handler、部分文件读取与旧聚合 ModelClient 接口仍是迁移债务，不宣称已全面完成 DDD 改造。

目标：以业务规则为核心的模块化单体。通用协议与模型配置分离，同协议新增模型无需修改执行代码，陌生协议通过明确扩展点接入。可阅读性、可测试性、数据兼容优先于抽象数量。

## 二、统一术语与建议领域边界

以下是目标职责边界，不意味着立即拆包、拆数据库或拆服务。旧 [术语表](domain-glossary.md) 中的 Provider 混合了连接与能力语义，新设计须使用下列明确术语。

| 概念 | 含义与约束 |
| --- | --- |
| 厂商 Vendor | 服务来源或品牌，不用于推断全部 API 协议 |
| 连接 Connection | 地址、访问范围、凭据引用与连接策略；凭据正文不属于领域实体 |
| 模型定义 ModelDefinition | 连接下的远端 ID、显示名称、启用状态和能力绑定；独立版本化配置 |
| 协议绑定 ProtocolBinding | 某项能力采用的请求、结果和任务生命周期协议及版本 |
| 能力规格 CapabilitySpec | 输入模式、允许参数、约束、结果类型、来源与修订；属于模型定义的配置值对象 |
| 验证记录 VerificationRecord | 验证范围、时间、配置修订和结果，不等同于模型启用状态 |
| 项目 / 草稿 / 分镜 | 创作组织、编辑版本和镜头内容；现有 Scene 用于分镜，与场景素材 Location 区分 |
| 素材 / 人物或场景设定 | 可复用媒体与带修订的创作设定；引用关系应可追踪 |
| 制作任务 / 生成运行 | 单次生成工作与其步骤关联；不能与分镜实体混为一体 |
| 成片 | 已选片段和输出设置的组合结果，不是一个新的 AI 模型能力 |

建议形成四个逻辑上下文：

1. **创作**：项目、草稿、分镜及设定引用，负责编辑、版本、结果采用与归属。
2. **模型目录与接入配置**：连接、模型定义、能力规格、协议绑定及验证记录。
3. **生成执行**：任务生命周期、冻结输入、远端任务跟踪、恢复、取消与重试。
4. **素材与成片**：素材生命周期、引用保护与成片制作；是否继续拆分由用例复杂度决定。

聚合设计以不变量为依据。现有 Project 携带草稿并整体持久化，不在文档阶段宣称已拆成独立 Draft 聚合；后续需分析并发写入、删除和原子操作后决定。连接与模型可作为不同聚合，通过 ID 关联，删除厂商及模型配置由用例协调事务。

## 三、DDD 分层和依赖

```text
interfaces/http、interfaces/websocket ──→ application ──→ domain
infrastructure ──→ application 定义的外部能力端口 / domain 仓储契约
cmd/server ──→ 组合以上实现并注入
```

领域层表达“允许什么”和“如何合法改变状态”；应用层表达“按何种顺序完成用户用例”；基础设施表达“通过什么技术完成”。对外 JSON、厂商字段和 SQL 行不能直接成为领域规则。

| 职责 | 应落位置 | 示例 |
| --- | --- | --- |
| HTTP 解析与响应 | interfaces/http | 解析生成请求、将领域错误转换成状态码 |
| 生成用例 | application | 读取配置、验证引用、生成快照、创建任务 |
| 业务规则 | domain | 状态迁移、输入模式限制、能力和参数合法性 |
| 执行编排 | application | 调用执行端口、恢复远端任务、协调结果回写 |
| 协议转换 | infrastructure/provider | 内部请求转厂商请求、解析结果、统一错误 |
| SQLite / 文件 / FFmpeg | infrastructure | 实现事务、素材存取、合成端口 |
| 初始化 | cmd/server | 注册协议、装配仓储和服务 |

端口归属消费方：聚合仓储契约可在领域包；网络、时钟、任务执行和通知端口一般在消费它的应用包。共享接口应小而明确，避免将所有功能塞进一个 `ModelClient`。

纯领域函数优先返回明确错误；由接口层统一映射用户提示和 HTTP 状态。错误至少区分配置缺失、协议不兼容、参数非法、认证失败、限流、临时不可用、远端任务失败与版本冲突。

## 四、设计模式使用边界

| 模式 | 采用位置与价值 | 使用限制 |
| --- | --- | --- |
| 端口与适配器 / 防腐层 | 隔离模型协议、数据库、媒体工具与传输机制 | 厂商 JSON 不泄漏到领域层 |
| Strategy | 按操作选择文本、图片、视频、语音执行策略 | 不建立“每模型一个策略类” |
| 显式 Registry | 按协议 ID、版本和操作查找适配器 | 在组合根注册，不通过模型前缀或全局变量查找 |
| Repository | 持久化聚合，统一并发版本语义 | 不要求每个数据库表都建仓储 |
| 窄事务端口 | 草稿删除、任务创建等跨写入一致性 | 数据库事务内不等待外部 I/O |
| 显式状态机 | 描述任务受理、轮询、取消、完成和恢复 | 优先类型与迁移表，不强制引入状态机框架 |
| 领域策略 / Specification | 复用确有变化的输入约束和资格判定 | 简单校验用普通函数，不为每个 if 创建对象 |
| 领域事件 / Outbox | 提交后可靠跨模块通知，确有需求时引入 | MVP 不默认事件溯源、消息中间件或双写存储 |

引入新模式前，在设计或 PR 中回答：哪一种变化被隔离？调用方是否更易读？能否独立测试？普通函数或接口为何不足？

## 五、统一模型扩展契约

### 5.0 连接与模型目录（2026-10-10）

厂商 `Connection.BaseURL` 只允许 HTTPS origin（域名和可选端口），接口路径归属模型协议。领域 `Connection.RequestURL` 负责组合，禁止跨主机路径；HTTP 适配器不得再次截取、补前缀或根据连接路径猜测协议。保存时去除末尾斜杠，前端展示最终地址。

模型目录由所选厂商的适配器确定，连接不保存额外同步方式。目录注册表按 `Connection.Vendor` 分派，独立于模型生成协议注册表。百炼原生读取 `/api/v1/models` 分页和能力元数据；其他兼容服务读取 `/v1/models`，ID-only 响应不能当作能力声明。未注册厂商明确提示手动添加，不探测或轮换接口。同步不能覆盖人工配置。当前项目未上线，此次依用户要求采用新契约，不新增旧连接迁移或路径回退。

### 5.1 配置与能力解析

目标结构是：连接提供访问配置，模型定义持有远端 ID 和一组“操作 → 协议绑定 + 能力规格”。同一厂商可提供不同协议，同一模型也可提供多种操作。

能力规格应包含：

- 操作：文本、图片、视频、语音；文本结果也可用于结构化分镜任务。
- 输入模式：纯文本、图片参考、单图首帧、多图参考、首尾帧、音频等，按实际协议逐项支持。
- 参数：枚举、范围或离散集合，以及默认值；例如分辨率、时长、比例、尺寸、参考图数量与文件上限。
- 输出：文本或媒体，单个或多个，同步完成或异步远端任务。
- 规格来源：适配器固有约束、厂商发现、内置预设、人工配置；附修订与验证状态。

可执行能力取**模型已配置能力、协议实现能力和当前操作要求的交集**。人工配置可以收窄协议允许的范围，不能突破其限制。发现结果缺少参数时由用户补充，不从名称推断为已支持；刷新发现结果不得无声覆盖人工配置，应产生可比较的新修订。

内置模型预设只负责便利填写。预设名不参与执行资格判断。手动添加一个陌生但真实的模型 ID，只要绑定已实现的协议并满足配置契约，就应进入相应功能列表。

### 5.2 统一调用过程

1. UI 获取后端解析后的能力、可用状态及原因，展示相应选项。
2. 用户提交，应用用例读取指定配置修订，再由领域规则验证参数、素材和归属。
3. 在事务中保存幂等任务与冻结输入，提交后再执行外部调用。
4. 执行器通过协议注册表取得适配器，将规范请求编码成厂商请求。
5. 适配器将同步结果或异步受理结果映射为统一结果；保存远端任务 ID，按策略轮询或接收回调。
6. 结果存储与创作结果应用通过相应端口和用例完成，校验取消、删除、旧版本及重复回写。

能力解析服务是前后端共享规则的唯一来源；缓存必须按配置修订失效。不能只修前端选项而让服务端、队列执行器或轮询仍按模型白名单拒绝。

### 5.3 配置状态与测试

`Enabled` 是管理意图；配置完整、协议已实现、连接验证和操作验证是独立状态。连接测试只证明其实际测试范围，模型列表请求成功不等于图片或视频生成成功。

UI 展示具体不可用原因和处理入口。暂时读取失败可重试，协议缺失需选择或实现协议，参数未配置需补充规格。不能统一显示“刷新重试”，也不能悄悄删除不匹配的选项。

### 5.4 任务与配置演进

快照冻结远端模型 ID、协议 ID/版本、能力修订、参数和素材修订。凭据只保留受控引用，密钥正文不进入快照；运行时读取密钥的轮换及访问规则必须明确。

旧配置迁移为显式绑定，无法推断的条目标记待配置并保留原值。旧任务没有协议快照时采用有版本、可追踪的兼容解析路径，不能直接套用当前默认模型。迁移应支持重复执行，覆盖历史任务、取消、删除标记及恢复。

新增协议需实现对应操作及任务生命周期；不支持的操作明确拒绝。新增同协议模型只增加配置或预设与契约测试，不修改 UI、用例或执行器分支。

## 六、可读性与工程组织

- Go 按业务职责组织包，导出的类型和方法表达业务意图；不以 `manager`、`common`、`utils` 堆放无边界逻辑。
- 通过构造函数、显式校验和有意义的方法维护不变量。Go slice/map 值需注意复制与别名，避免“不可变快照”被共享引用修改。
- 应用用例不依赖 Gin Context；传递标准 `context.Context` 和具体命令/查询 DTO。
- 协议请求结构使用明确类型；确需厂商扩展字段时限制在适配器边界，并定义允许字段与校验。不要设计可执行任意脚本的 JSON 模板引擎。
- Vue 模板、请求状态、参数校验和复杂业务编排分开；可复用交互提取 composable。接口类型从 OpenAPI 生成，错误提示包含用户可执行的下一步。
- 日志包含任务 ID、模型配置 ID、协议及修订、阶段、耗时和错误类别；去除密钥、授权头、带凭据的 URL 和不必要的用户输入。
- 协议适配器定义超时、取消、有限重试、大小限制和结果校验；对不确定是否被远端受理的请求保留未知状态与恢复路径。

## 七、开发流程与检查

1. 读取守则、规格和代码，记录问题证据、影响面、数据与兼容约束。
2. 架构或跨模块修改先说明候选方案、领域边界、契约与迁移，再拆分可验收任务。常规小修复沿用现有约定。
3. 实现按用例纵向推进，每次提交范围包含需要的规则、应用服务、适配器、接口及测试，不先造一套空框架。
4. 更新 OpenAPI、相关指南和迁移记录，核验 UI 与服务端使用同一契约。
5. 按改动影响执行测试并报告结果；受当前用户要求限制时明确本轮范围，不自动跨入实施或发布。

常用命令（在标明的目录运行）：

| 目录 | 命令 | 用途 |
| --- | --- | --- |
| backend | `go test ./...` | 后端测试；涉及合成时配置真实 FFmpeg/ffprobe，核对是否跳过相关测试 |
| backend | `go vet ./...` | 静态检查 |
| frontend | `npm run api:generate` | OpenAPI 变更后生成类型 |
| frontend | `npm run lint` | 前端静态检查 |
| frontend | `npm test` | 单元和组件测试 |
| frontend | `npm run build` | 类型检查与生产构建 |
| frontend | `npm run e2e` | 使用独立临时数据库、上传与密钥目录的端到端回归 |
| 仓库根 | `git diff --check` | 差异格式检查 |
| 仓库根 | `./scripts/build-windows.ps1` | Windows 打包；可用 `FRAMEFLOW_FFMPEG_DIST_DIR` 指定已有工具目录 |

文档阶段只检查事实、相对链接和差异。正式测试包按 [发布说明](release.md) 执行相关全套检查；容器交付才要求对应容器验证。模拟测试不替代真实服务验证，真实调用须另有授权。

模型体系的最低回归矩阵：文本/图片/视频/语音各自的已知与陌生模型 ID；多个连接；同步和异步协议；输入模式不兼容；参数范围冲突；认证/限流/超时；取消与迟到结果；重复提交；重启恢复；旧数据升级；配置删除或变更后的运行中任务。

## 八、下一阶段的进入条件

统一模型接入规格和实施记录已落在 `specs/model-protocol-integration/`。继续扩展时，先记录 wire format、参数与生命周期契约，再增加协议描述、窄端口适配器和测试；不要恢复模型名判断。未知厂商参数须有文档或契约证据，不能猜测。
