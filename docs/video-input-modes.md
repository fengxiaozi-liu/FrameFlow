# 视频生成模式与首尾帧选择

日期：2026-10-10。

## 交互与规则

- 模型管理的“支持的生成模式”可同时勾选首尾帧和智能参考（多图）。只支持首帧的模型取消“支持尾帧图片”。参数按服务商实际支持范围填写，勾选不代表已通过真实生成验证。
- 分镜选择模型后，单一模式直接展示；同时支持两种模式时，由用户选择本次模式。
- 首帧必选，尾帧可选。候选图来自当前分镜实际引用的图片，展示名称和预览。用户可将同一张图用于起点与终点。不根据引用排序自动指定图片用途。
- 智能参考提交全部当前引用图片，按素材 ID 去重，遵守模型的最大参考图数量。切换模式保留已有首尾帧选择，提交时仅发送当前模式需要的字段。
- 首尾帧模式只提交选定图片，其他人物、场景设定保留。图片移除后显示重新选择提示，禁止提交失效选择。
- 模式、首尾帧素材 ID、素材内容摘要及模型配置进入任务快照。任务详情展示提交时的首尾帧，重试沿用冻结快照。
- 点击“生成视频”后留在分镜详情，下方“生成记录”显示各任务状态、视频进度、失败原因和完成结果预览；需要选用、重试或取消时可进入对应任务详情。
- 已有任务处理中不阻止再次生成。每次成功提交后的新点击创建独立任务并冻结当次输入；提交期间禁用按钮，网络中断后的恢复沿用原幂等键，避免重复创建。实际执行仍遵守任务队列和服务商的并发限制。
- 任务中心与任务详情提供“返回分镜”入口；任务中心仅在原分镜仍存在时展示该入口。视频预览按媒体实际尺寸保持比例并限制展示宽高，任务详情在宽屏下将视频与生成设定分栏，窄屏下改为上下排列。

## 领域与协议设计

`OperationBinding.input_modes` 表达模型支持的模式集合；`GenerationSettings.video_input_mode` 表达本次选择；`first_frame_material_id` 与 `last_frame_material_id` 表达图片用途。避免把能力声明与执行选择混在一个单选属性中。

领域方法 `SelectVideoMode` 和 `VideoCapabilityFor` 解析指定模式的约束；应用层负责检查图片属于当前分镜、读取素材并冻结输入。协议适配器消费明确的 `VideoRequest.InputMode`，编码首帧/尾帧或参考图片。首尾帧和智能参考禁止混用。轮询依赖协议，不依赖模型仅支持一种输入方式。

复用现有端口与适配器及配置策略，不新增模型名称白名单或通用工作流。当前两种模式共用比例、时长、清晰度和图片大小限制；多图数量只作用于智能参考。若服务商两种模式使用不同请求格式或参数范围，需扩展模式级协议绑定，不能仅凭勾选宣称支持。

自定义 JSON 模板可读取 `input_mode`；同时声明两种模式时必须映射 `images` 和 `first_frame`，声明尾帧还需映射 `last_frame`。空字段如何被服务商接受仍以接口契约为准。

## 数据兼容与恢复

新增可选 JSON 字段，无数据库表结构迁移。旧 `input_mode` 作为单模式配置读取；显式 `input_modes` 优先，不重新猜测模型能力。旧任务快照未包含新字段时保持原指纹和单模式执行行为。

更新前按发布指南备份数据目录。旧版本无法识别双模式配置与新任务语义，因此回滚应恢复更新前数据备份，不能直接将新增配置交给旧程序执行。新程序不重写历史任务和真实用户配置。
