## 摘要

按“正文 → 分镜 → 视频”重建项目工作台：正文可直接编辑或由故事联想生成候选后显式应用；正文生成独立的分镜候选，确认后替换且保留恢复点；素材按用途绑定到具体镜头；视频任务保存提交时输入与历史版本；最后按选定版本和镜头顺序拼接、混音并下载。素材库改为场景、角色、道具、配音、音乐，兼容已有分类和文件。范围覆盖 RQ-101～RQ-120；交互细节以设计基线为准。

旧计划的“故事和分镜一次生成、无冲突时自动回写、image/video 业务不变”不再适用。旧 RQ-001～RQ-008 仅供了解技术背景，不能当作本计划的验收要求。可复用其结构化输出校验、服务端镜头 ID、任务作用域与幂等思路。

## 项目适配输入

- 项目类型：Go/Gin 后端，领域、应用、基础设施分层；Vue 3/Pinia 前端；SQLite 中以 JSON 负载保存项目、任务和素材。
- 结构约束：领域对象在 `backend/internal/domain`，用例在 `application`，百炼协议在 `infrastructure/provider`，HTTP/OpenAPI 在 `interfaces/http` 与 `docs/api/openapi.yaml`；前端类型、store、视图分别在 `frontend/src/api`、`stores`、`views`。
- 现状：`story.Document` 含正文与分镜，但故事任务只回写 `body`；`task.Input` 只有 prompt、画幅、单张来源图；素材是 visual/character/frame/voice/music；现有项目页和素材页尚无本规格所需的绑定、版本与合成能力。
- 交付物类型：领域与存储兼容改造、API/OpenAPI、供应商能力适配、前端页面及状态、成片服务、迁移和回归验证、操作文档。
- 特殊验证要求：历史数据库样本迁移与回滚演练；Go、前端及端到端测试；模型能力核实与真实配置冒烟；图片与提示词只作视觉参考（RQ-120）。

### 依赖调研

| 依赖对象 | 用途 | 已有能力 | 需要新增或修改 |
|----------|------|----------|----------------|
| 百炼故事模型 | 故事联想、正文拆分镜 | 自由文本结果，单条用户消息 | 分开两个生成目标，使用有版本的 system/user 提示词；支持的模型可用 JSON Object/Schema，服务端仍严格校验并保存候选 |
| 百炼 Wan 2.7 图生视频 | 单镜头生成 | 现有适配只提交 `first_frame`，未提交时长、清晰度、尾帧或音频 | 按官方协议支持首帧、首尾帧及可选驱动音频；限制为整数 2～15 秒、720P/1080P；其他参考图用途先保留在草稿但阻止提交 |
| 成片媒体工具 | 拼接与混音 | 未见成片服务，本机未发现 `ffmpeg` 命令 | 采用 FFmpeg 子进程；容器安装，Windows 发行包随包提供并校验可执行文件；统一转码后拼接和混音 |
| SQLite JSON 仓储 | 持久化及历史兼容 | 项目、任务、素材已有 JSON payload | 增加可选字段与查询/引用索引；设计迁移、备份、重复运行和回滚验证 |
| WebSocket / 任务队列 | 异步状态 | 有作用域任务事件、重试和下载 | 候选、版本及合成任务按 ID 去重，刷新后能恢复 |
| 前端工作台 | 编辑与素材管理 | 基础 StudioView、MaterialsView、Pinia | 拆分三页工作流、镜头检查面板、素材选择、状态恢复和键盘操作 |

已核实的首个视频能力配置仅针对仓库现有 `wan2.7-i2v` 适配：一个 `first_frame` 必需，可再加一个 `last_frame`、一个 `driving_audio`；各类型最多一个，角色/场景/道具多图参考不能作为这个模型的生成输入。图片最大 20 MB，驱动音频仅 wav/mp3、2～30 秒、最大 15 MB；视频时长为整数 2～15 秒，输出 720P 或 1080P。驱动音频超出视频时长时提供者会截断，因此应用层须先阻止并提示。上传通用上限不能代替模型上限。图片可使用数据 URI；音频需提供商可访问的 URL，本地 `/media/` 相对路径不能直接发送。生产环境采用配置的对象存储提供音频；供应商临时上传 URL 仅用于开发/测试，不作为正式依赖。未配置可访问的音频存储时禁用“生成参考音频”提交并说明原因，镜头后期配音仍可在本地合成。其他模型的能力保持“未知/不可提交”，直到新增适配和验证。[百炼 Wan 2.7 API](https://help.aliyun.com/en/model-studio/image-to-video-general-api-reference)、[模型能力概览](https://help.aliyun.com/en/model-studio/use-video-generation)、[临时文件限制](https://help.aliyun.com/en/model-studio/get-temporary-file-url)。

百炼任务与视频结果链接只在 24 小时内有效。视频任务成功后须立即下载并持久化文件，文件校验完成才创建可选版本；下载失败可重试且不把临时链接当作保留版本。[百炼结果说明](https://help.aliyun.com/en/model-studio/image-to-video-general-api-reference)。

### 调研结论

- **DR-001：生成结果的应用边界**
  - 决策：正文与分镜分别生成持久化候选，由用户预览并显式应用；草稿版本不匹配时再次确认。
  - 理由：保护生成期间的编辑，并让已有正文用户跳过故事联想（RQ-102～105）。
  - 排除方案：故事任务自动改写正文和分镜，或无冲突时自动应用。
- **DR-002：分镜替换与身份**
  - 决策：镜头 ID 由服务端生成；候选整批替换，旧分镜连同绑定及版本保留为恢复点；排序只改变 order。
  - 理由：不能按序号推断镜头身份或把旧素材串到新镜头（RQ-105、106）。
  - 排除方案：按位置自动合并，或替换时删除旧数据。
- **DR-003：素材类别和用途**
  - 决策：素材类别与镜头绑定用途分离；旧 visual 映射场景，旧 frame 保留 ID/文件并暂归场景且标记来源；原有明确用途保留。
  - 理由：同一素材可跨镜头按不同用途使用，历史任务输入不能被改写（RQ-107～109、114～117）。
  - 排除方案：全局“当前选用”素材，或迁移时重建文件与 ID。
- **DR-004：任务与版本**
  - 决策：任务创建时固定 project/draft/scene、输入和能力版本；成功输出新增视频版本，只有首个匹配结果可默认选用。
  - 理由：防止晚到结果跨草稿、覆盖新编辑或抢占已选片段（RQ-110～112）。
  - 排除方案：只在镜头上保存单个 result_url。
- **DR-005：成片合成**
  - 决策：后端执行简单顺序拼接与音频混合，提交前完整校验片段；合成任务固定有序版本和设置，结果可下载。
  - 理由：满足 RQ-113，同时避免前端临时拼接不可复现。工具与规范化策略见 DR-008。
  - 排除方案：把预览当成可下载成片，或自动导出不完整片段。
- **DR-006：能力来源**
  - 决策：模型能力采用经核实的服务端配置，由后端校验并在前端展示；未知和未支持按不可提交处理。
  - 理由：供应商的“video”标签不足以推出多图、音频、尾帧与任意时长支持（RQ-108～110）。
  - 排除方案：仅在界面隐藏字段，后端默默忽略已绑定输入。
- **DR-007：故事与分镜的结构化输出**
  - 决策：后端分目标维护版本化 system/user 提示词；模型支持时优先 JSON Schema，否则使用 JSON Object，响应一律经服务端解析和领域校验。故事联想只需正文，拆分镜只需镜头数组；提示词版本与源正文快照记在任务中。
  - 理由：百炼官方仅为部分模型提供严格 JSON Schema，JSON Object 只保证语法，不能代替字段验证；这避免沿用旧计划强制一次生成正文和分镜。[百炼结构化输出](https://help.aliyun.com/en/model-studio/qwen-structured-output)。
  - 排除方案：依赖自由文本正则抽取，或把概念图提示词当作运行时系统提示词。
- **DR-008：成片执行与发行**
  - 决策：使用 FFmpeg 子进程和 ffprobe 获取真实媒体信息；输入先统一帧率、画幅和音频格式，等比缩放加留边后拼接，按镜头时长叠加配音并混入背景音乐。背景音乐不足时循环到片尾，配音超长则在提交前拒绝。FFmpeg 与服务端同机运行，容器镜像和 Windows 发行包均须提供可执行文件及启动检查。
  - 理由：不同片段流参数可能不同，直接流复制拼接不可靠；FFmpeg 提供重编码拼接与混音能力。[FFmpeg 拼接说明](https://ffmpeg.org/faq.html)、[滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)。
  - 排除方案：浏览器端合成，或未经规范化即直接复制流拼接。
- **DR-009：旧数据迁移和引用完整性**
  - 决策：先备份数据库与媒体目录，在 SQLite 事务中执行可重复的版本化迁移；保留旧素材与任务 ID，新增候选、镜头绑定、视频版本、成片的持久化记录及引用索引。旧分类按规则映射；旧全局选中信息不推断为所有镜头绑定。旧任务缺镜头归属时只在任务中心展示，不能自动关联新镜头。
  - 理由：项目与任务是 JSON payload，无法仅靠修改前端分类完成引用保护；历史数据必须可读且可恢复。
  - 排除方案：删除旧表或文件后重建，或仅在页面中做分类映射。
- **DR-010：异步任务与文件的原子边界**
  - 决策：数据库记录与媒体文件分阶段提交：先写临时文件并校验，再原子重命名并提交记录；失败保留可重试任务并清理临时文件。成片也采用同一约定；后台回调以 task ID 去重。
  - 理由：文件系统与 SQLite 不共享事务，必须避免成功任务指向不存在的文件。
  - 排除方案：一收到远端 URL 就标记镜头版本成功。
- **DR-011：生成参考音频的传输**
  - 决策：在供应商适配层使用配置的对象存储生成有期限的、供应商可访问的音频 URL；提交前检查可达性与有效期。没有这项配置时保留素材绑定，但阻止将其作为生成参考提交，仍允许用于本地后期配音。
  - 理由：百炼驱动音频要求 URL，现有 `/media/` 是相对本地路径；官方临时上传明确不推荐正式高并发场景。[百炼音频输入](https://help.aliyun.com/en/model-studio/image-to-video-general-api-reference)、[临时存储说明](https://help.aliyun.com/en/model-studio/get-temporary-file-url)。
  - 排除方案：把本机文件路径或相对 URL 直接发送给供应商。

### 协议 / 接口设计（若适用）

以下为接口契约方向，具体路径、状态码及分页在任务拆解前统一到 OpenAPI；避免为同一编辑操作同时保留相互矛盾的入口。

| Candidate | 创建、查询、应用、撤销/恢复 | scope、目标 story/storyboard、输入快照、expected_version | candidate_id、预览、任务状态、恢复点 | RQ-103～105 |
| Material | 上传、列表、详情、更新、删除 | 分类、标签、媒体筛选、搜索、排序 | 元数据、使用位置、删除阻止原因 | RQ-114～117 |
| Scene Binding | 列表、确认绑定、解除绑定 | scope、scene_id、material_id、用途 | 绑定及兼容性 | RQ-107～109 |
| Model Capability | 查询可用模型与输入限制 | model_id | 支持用途、数量、时长、画幅及未知原因 | RQ-108～110 |
| Video Task | 单镜头/批量创建、重试、查询 | scene_id(s)、model_id、expected_version | 每镜头校验/创建结果、任务输入摘要 | RQ-110、111、118 |
| Video Version | 列表、选择 | scope、scene_id、version_id | 历史版本、已选、与当前输入是否一致 | RQ-111、112 |
| Composition | 创建、查询、下载 | 有序 version_id、配音/音乐、音量、输出参数 | 校验缺项、状态、成片 URL | RQ-109、113 |

现有 `POST /api/tasks`、任务查询/重试、项目及素材接口应保持历史客户端可读；新字段可选或使用明确版本的新动作。服务端始终从已保存草稿和素材读取权威数据，不信任客户端伪造的旧正文、文件路径或镜头归属。任务结果按 project/draft/scene 校验后落库；已删除镜头结果仅在任务中心显示。

### 数据或配置设计（若适用）

| 对象 | 字段或配置项 | 类型 | 约束 | 说明 |
|------|--------------|------|------|------|
| Draft | version、body、scenes、candidates、storyboard_snapshots | 版本号与结构化 JSON | 保存采用期望版本；旧草稿缺字段时可读取 | 保留候选与恢复点 |
| Scene | id、order、title、visual_prompt、narration、duration_seconds、aspect_ratio | 结构化 JSON | id 稳定、order 连续、复制新 ID | 镜头身份不随排序变化 |
| Material | id、kind、legacy_kind、tags、media_info | JSON + 文件 | kind 为五类；保留旧 ID、URL 和旧分类来源 | 图片尺寸、音频时长从文件读取 |
| Binding | project_id、draft_id、scene_id、material_id、usage、position | 关系记录 | 首/尾帧各最多一张；引用必须存在 | 用途与素材类别分离 |
| Task | target、scene_id、input_snapshot、capability_version、status | JSON | 创建时固定；结果幂等；旧任务可反序列化 | 正文、分镜、视频、合成分目标 |

| Composition | clip_versions、order、audio、levels、format、output | JSON + 文件 | 只引用已存在可用版本；提交时快照 | 保留历史成片 |
| ModelCapability | usages、counts、duration、aspect_ratios、size_limits、output_formats | 服务端配置/能力记录 | 未知值不可提交；每项有核实来源 | UI 与服务端共用限制 |
| MediaDelivery | 对象存储凭据、区域、桶、URL 有效期 | 服务端配置 | 不回显凭据；生成参考音频前验证可用 | 向模型提供可访问音频；本地合成不依赖此项 |
| CompositionRuntime | ffmpeg/ffprobe 路径、超时、临时目录 | 服务端配置 | 启动时检查可执行文件及写入权限 | 容器和 Windows 包均需交付 |

先编写迁移策略与旧数据 fixture，再变更持久化：旧 visual → 场景；旧 frame → 场景并标“原首尾帧”；character/voice/music 对应保留。迁移必须可重复执行，并验证文件、ID、任务输入和明确绑定用途不变。JSON 字段扩展之外，如引用查询需要新表或索引，应在 SQLite 迁移中单独设计；不能仅以 UI 过滤代替引用保护。

- `go test ./...`、`go vet ./...`；相关并发/存储用例在环境支持时跑 race 检查。
- `npm run lint`、`npm test`、`npm run build`、`npm run e2e`；OpenAPI 生成类型同步并检查差异。

## 风险与边界

| 风险项 | 影响 | 缓解措施 |
|--------|------|---------|
| 非 Wan 2.7 模型输入能力未知 | 其他模型绑定可能无法提交 | 默认不可提交，新增模型需独立能力配置和冒烟验证 |
| FFmpeg 或对象存储在运行环境缺失 | 合成或驱动音频生成无法执行 | 发行包/容器交付检查；按受影响能力显示未开放或配置错误，不影响本地编辑 |
| 供应商结果链接 24 小时失效 | 历史视频版本无法播放或合成 | 成功后立即下载到持久存储，文件校验后才标记版本可用 |
| 历史素材分类与全局选用混杂 | 旧项目引用丢失或被错误扩散到镜头 | 迁移保留身份及显式用途；未知全局选中不自动分配给所有镜头 |
| 并发保存与异步结果晚到 | 编辑、已选版本或其他草稿被覆盖 | 版本条件更新、输入快照、作用域检查、结果幂等和恢复点 |
| 素材文件被删除或媒体格式不兼容 | 视频任务/成片失败 | 引用保护与提交前重新检查；媒体元数据及合成能力校验 |
| 范围扩大到专业剪辑或自动配音 | 实施无法闭环 | 维持简单拼接、配音混合与下载；多轨剪辑、逐字字幕和自动配音不在本计划内 |
